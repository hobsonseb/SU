# 업무 자동화 프로젝트 최종 보고서

## 0. 핵심 개념 이해 
* **Trigger와 Action의 개념:**
  - Trigger(트리거): 자동화 워크플로우를 시작하게 만드는 '조건'이나 '사건'입니다. (예: 구글 시트에 새로운 데이터가 입력될 때)
  - Action(액션): 트리거가 발생한 후 실제로 수행되는 '작업'입니다. (예: 특정 담당자에게 이메일을 발송하는 것)
* **조건 분기(Filter/Router)의 역할:**
  - 들어온 데이터의 조건에 따라 이후의 작업 경로를 여러 갈래로 나누는 '교차로' 역할입니다. 이를 통해 하나의 워크플로우 안에서 상황에 맞는 다양한 맞춤형 Action을 실행할 수 있습니다.
* **특정 업무에 적합한 도구 선택 및 이유:**
  - 조건 분기가 필요 없고 단순한 1:1 연결이 필요할 때는 직관적인 **Zapier**가 적합하지만, 본 과제처럼 조건 분기(Router)와 다중 Action이 필요한 복잡한 업무를 비용 없이 구축할 때는 **Make.com**이 가장 적합합니다.

## 1. [프로젝트 1] 자동화 도구 비교 구현

* **사용한 도구 이름:** Zapier vs Make.com
* **구현 과정 요약:** '데이터 입력 시 이메일 자동 발송'이라는 동일한 워크플로우 구조를 두 가지 도구로 각각 구현해 보며 UI와 설정 방식을 비교 분석함.
* **비교 분석 보고서 (5개 항목):**
  1. UI/UX: Zapier는 위에서 아래로 흐르는 직선형 구조라 초보자가 이해하기 쉽고, Make는 노드(동그라미)를 자유롭게 배치하는 시각적 마인드맵 형태라 복잡한 구조를 한눈에 파악하기 좋습니다.
  2. 설정 난이도: Zapier가 가이드가 친절하여 진입 장벽이 낮으나, Make는 세부적인 데이터 매핑 시 약간의 구조적 이해가 필요합니다.
  3. 무료 플랜 범위: Zapier는 무료 버전에서 조건 분기(Path)나 다중 Action이 불가능하지만, Make는 무료 플랜에서도 라우터(조건 분기)와 무제한 Action 연결을 지원하여 실습 및 실무 적용에 매우 유리합니다.
  4. 연동 서비스 범위: Zapier가 전 세계적으로 가장 많은 앱 연동을 지원하며, Make도 주요 앱들은 대부분 지원하나 국내 앱 연동은 둘 다 다소 제한적입니다.
  5. 실행 로그 확인: 두 도구 모두 실행 기록을 제공하지만, Make는 워크플로우 화면 내에서 데이터가 어떻게 흘러갔는지 돋보기 아이콘과 애니메이션으로 즉각적인 시각화(Visual Log)를 제공하는 점이 뛰어납니다.
* **각 도구의 장단점 및 적합한 상황:**
  - Zapier: (장점) 쉽고 연동 앱이 압도적으로 많음 / (단점) 무료 플랜 제한이 큼 / (적합) 단순 1:1 자동화.
  - Make.com: (장점) 무료로 복잡한 다단계/분기 자동화 가능 / (단점) 초기 학습 곡선이 있음 / (적합) 조건 분기가 포함된 다중 작업 자동화.

## 2. [프로젝트 2] 자유 주제 자동화 설계 및 구현

* **자동화할 반복 업무 1개 정의:**
  - 업무명: 고객 문의 유형에 따른 담당자 자동 배정 및 맞춤형 이메일 발송
  - 정의: 구글 시트에 고객의 문의(긴급도 높음/낮음 등)가 접수되면, 사람이 일일이 확인하여 전달할 필요 없이 조건 분기를 통해 각 상황에 맞는 이메일이 자동으로 발송되는 업무.
* **도구 1개 선정 및 선정 이유:**
  - 선정 도구: Zapier (또는 Make.com)
  - 선정 이유: 조건 분기(Router/Paths)를 활용하여 데이터의 성격에 따라 서로 다른 Action(이메일 발송)을 실행하는 흐름을 직관적으로 설계하고 테스트하기 위함.
* **자동 실행 구조 구현 및 워크플로우 흐름 설명:**
  - 1단계 (Trigger): `Google Sheets` - 시트에 새로운 데이터(행)가 입력되는 것을 감지하여 워크플로우를 시작합니다.
  - 2단계 (조건 분기): `Router(Paths)` - 구글 시트에서 불러온 '긴급도' 데이터에 따라 경로를 2가지로 나눕니다.
  - 3단계 (Action 1): `Path A (긴급도=높음)` ➡️ `Gmail` - 긴급 건일 경우, 담당자에게 즉시 확인을 요청하는 메일을 발송합니다.
  - 4단계 (Action 2): `Path B (긴급도=낮음)` ➡️ `Gmail` - 일반 건일 경우, 순차적으로 처리될 예정임을 알리는 안내 메일을 발송합니다.

## 3. 트러블슈팅 및 배운 점 (Troubleshooting)
* **문제 발생:** Action 단계에서 Gmail 설정을 마쳤으나, 초기 테스트 시 메일이 발송되지 않거나 에러가 발생하는 현상을 겪음.
* **원인 및 해결:** 이메일 설정 창(Configure)에서 필수 항목인 `To(받는 사람)`, `Subject(제목)`, `Body(본문)`가 비어있었기 때문임을 파악함. 또한, 본문에 텍스트를 직접 입력하는 것이 아니라, Trigger(구글 시트)에서 불러온 **동적 데이터(알약 형태의 변수)**를 클릭하여 매핑(Mapping)해주어야 실제 데이터가 연동된다는 것을 깨닫고 수정하여 해결함.
* **인사이트:** 노코드 자동화 툴은 매우 직관적이지만, 컴퓨터에게 '누구에게, 무엇을' 보낼지 정확한 변수 데이터를 매핑해주는 과정이 필수적이라는 것을 배움.

## 4. 실무 활용 사례 및 기대 효과
본 과제에서 구축한 **[데이터 입력 ➡️ 조건에 따라 분류 ➡️ 맞춤형 메일 발송]** 시스템은 실무의 다양한 영역에서 응용될 수 있습니다.
1. **고객 서비스 (CS) 자동화:** 고객 문의 접수 시 '환불/불만' 카테고리는 CS 팀장에게 긴급 알림(Path A), '단순 문의'는 일반 담당자에게 배정(Path B)하여 응대 속도를 높일 수 있습니다.
2. **채용 및 인사 관리 (HR):** 면접 평가 시트에서 합격/불합격 여부를 체크하면, 합격자에게는 다음 면접 안내 메일을, 불합격자에게는 위로 메일을 자동 발송하여 HR 부서의 반복 업무를 줄일 수 있습니다.
3. **영업 및 마케팅 (Sales):** 홈페이지에서 고객이 입력한 예산 규모에 따라 VIP 영업 사원에게 즉시 연결하거나, 자동화된 상품 안내 브로셔를 발송하는 등 리드(Lead) 관리를 효율화할 수 있습니다.
